# 操作与运维手册

## 双行业演示

1. 启动服务，访问首页进入摄影或餐饮示例，页面上的商家、插画和活动均为演示内容。
2. 使用摄影店主登录，在店铺设置完善资料、Logo；创建活动，设置档期、容量、时间、价格和规则。
3. 保存后可生成离线文案建议；逐项审核、确认素材使用权限，发布并复制渠道链接或二维码。
4. 在顾客页面选择档期、填写联系方式并确认隐私说明。保存回执及隐私凭证。后台可确认、完成或取消预约。
5. 使用餐饮店主发布领券活动，在顾客页面领券；用餐饮店员登录核销同一张券，再次核销会被拒绝。
6. 在数据与洞察查看事件、来源及趋势。预约导出和审计仅限店主。平台管理员可手动开通新店主。

活动发布后需先暂停再编辑关键内容，重新审核发布。已结束活动不能重新发布；可复制为新草稿。删除顾客资料使用其编号与隐私凭证，不直接修改数据库。

## 备份与恢复

运行 `npm run backup`，默认生成 `.local/backups/` 下的 SQLite 快照。也可指定新文件：

```powershell
npm run backup -- .local/backups/manual.sqlite
```

脚本使用 SQLite 在线备份 API，不复制正在写入的主文件来代替快照。图片已存于数据库中，随快照备份。加密密钥需另行安全保存。

恢复必须指定不存在的新目标：

```powershell
npm run restore -- .local/backups/manual.sqlite .local/restored.sqlite
```

脚本先检查快照完整性。停止服务，将 DATABASE_PATH 改为恢复文件并保留原 DATA_KEY；若通过自动 key 文件配置，确保恢复路径对应目录仍能取得原 key，再重新启动。确认登录、店铺、预约和核销可用后，才切换实际操作到恢复库。快照之后的变更不会出现在恢复结果中。

## 检查与回滚

`npm run verify` 汇总类型检查、lint、单元/接口测试、构建、E2E 和运维演练。`npm run test:ops` 在独立 `.local/rehearsal-*` 目录创建两个本地版本，验证版本切换、在线快照、恢复及原页面内容；它不操作云资源，也不能证明跨数据库结构升级回滚安全。

手工版本回滚应先停止服务、备份当前数据库，恢复已验收的完整代码与依赖锁，再使用匹配数据库结构的快照及原密钥启动。存在结构迁移时须先制定专门的数据兼容和恢复方案。

最终验证结论及日志索引见 [TEST_REPORT.md](TEST_REPORT.md)，不要把截图或页面可访问等同于全部接口通过。

## 故障定位与指标

| 现象 | 检查 |
| --- | --- |
| 服务无法启动 | Node 是否为 24；4173 是否占用；数据库目录是否可写；DATA_KEY 是否有效 |
| 页面空白或缺资源 | 重新执行 npm run build，确认从项目目录运行 npm start |
| 写请求 403 | 访问地址与 PUBLIC_ORIGIN 是否一致；重新登录刷新 CSRF |
| AI 503 或额度耗尽 | 默认使用 Mock；检查真实适配配置或改为手动编辑 |
| 预约/领券 409 | 活动有效期、档期容量、每日额度、同浏览器领取上限或状态冲突 |
| 旧数据无法解密 | 恢复时是否使用原 DATA_KEY / key 文件；不要生成替代密钥覆盖原文件 |

统计来自真实操作事件。UV 是匿名浏览器标识去重，不能视为真实人数；预约/领券是行为，不是支付成交额。近 7 日趋势按中国标准时间分日，演示环境所有指标都应作为演示数据解释。
