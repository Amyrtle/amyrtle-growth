# 安全实现与边界

本版本为本地 MVP。启动入口强制绑定回环地址；演示账户与已知演示密码仅适用于本机验证。以下是代码中的控制及其适用范围，不代表完成生产安全认证。

## 已实现

- 密码使用随机盐和 scrypt；会话令牌数据库保存 SHA-256 摘要，8 小时到期。Cookie 为 HttpOnly、SameSite=Strict；HTTPS origin 下启用 Secure。
- 写请求要求自定义来源标记；校验请求 Origin，已登录写请求另验证会话 CSRF。Helmet 设置响应头和 CSP。
- owner / staff / admin 权限由服务端会话获取；商家资源查询带 tenant 条件，复合外键补充数据库归属约束。店员不能编辑店铺或活动、上传素材、导出全部预约或查看审计。
- 预约姓名及手机号采用 AES-256-GCM 加密。券码由密钥派生、数据库只保存校验摘要；隐私操作验证高熵凭证摘要。
- SQLite WAL、外键、检查约束及 BEGIN IMMEDIATE 事务保护名额、发券、核销、关键状态与审计；提交支持幂等处理。
- 登录、公开操作、隐私操作、核销、图片和 AI 有频率或额度限制；记录核销成功/拒绝及关键管理动作。
- Zod 严格字段校验；文案拒绝 HTML 标签；图片校验格式与像素，重新编码为 WebP，并校验商户归属和素材确认。
- AI 默认使用不联网 Mock；真实模型输入只含店铺与活动事实。模型结果需结构校验、基础事实检查和人工发布审核。

## 明确限制

SQLite 没有 PostgreSQL RLS；当前为应用层租户隔离与数据库约束。尚未完成 CloudBase 身份、RLS、直连数据库防护、多实例部署或真实模型服务验证。

访客身份依赖浏览器 Cookie，清 Cookie、换设备可绕开每访客领券额度，当前没有手机验证码、实名识别或分布式反滥用系统。IP 限流也不能替代生产防刷。

资料删除会清除预约联系方式，并取消未完成预约或撤销未用券；匿名业务记录、事件和审计会保留。没有自动保留期清理任务；备份中的旧数据需要单独管理。隐私凭证持有者可查询或删除对应记录，应避免公开传播凭证。

AI 事实检查是有限规则，不能证明宣传内容正确或合规。所有公开内容仍需商家逐项审核。

## 配置与响应

`.env`、`.local/` 与密钥不应进入源代码仓库。DATA_KEY 是 64 位十六进制字符串；本地未配置时自动生成数据库同目录下的 `key`。数据库备份与密钥应分开保存，恢复时必须使用原密钥。Windows 上需由操作系统管理员配置合适的目录 ACL。

遇到数据或权限异常：停止相关操作，记录 requestId 和发生时间，保留日志及数据库快照，修复后回归租户隔离、幂等与核销测试。不要把真实联系方式、会话、券码、隐私凭证或 API 密钥贴入公开日志。

正式上线还需根据实际环境完成 HTTPS、密钥托管、账户生命周期、数据保留/删除、监控告警、备份演练与独立权限审查。当前验证证据见 [TEST_REPORT.md](TEST_REPORT.md)。
